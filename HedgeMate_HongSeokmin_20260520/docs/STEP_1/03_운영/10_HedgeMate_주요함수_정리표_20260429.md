# HedgeMate 주요 함수 정리표 (2026-04-29)

## 1. 문서 목적
이 문서는 현재 HedgeMate 프로젝트를 빠르게 이해할 수 있도록
핵심 함수만 추려서 정리한 요약 문서이다.

정리 기준은 아래와 같다.

- 실제 실행 흐름에 직접 들어가는 함수 위주
- 작은 수학 유틸 함수나 단순 포맷팅 함수는 제외
- `엔진`, `대시보드 서버`, `웹 UI` 순서로 정리

---

## 2. 전체 흐름 한눈에

HedgeMate의 큰 흐름은 아래처럼 이해하면 된다.

1. `scripts/run_data_pipeline.py`
   - 입력 자산/포트폴리오를 읽고
   - 리스크 지표를 계산하고
   - 헷지 후보를 고른 뒤
   - 추천 결과와 문서를 만든다.

2. `scripts/serve_dashboard.py`
   - 웹 요청을 받아 분석 실행을 준비하고
   - 파이프라인을 호출하고
   - 결과 CSV/MD를 읽어서 대시보드용 JSON으로 정리한다.

3. `web/app.js`
   - 서버에서 JSON을 받아
   - 비교표, 추천안, 민감도, 산출물 링크를 화면에 렌더링한다.

---

## 3. 엔진 주요 함수

대상 파일: `scripts/run_data_pipeline.py`

| 함수 | 리턴값 | 역할 |
|---|---|---|
| `load_portfolio_input()` | `(input_path, weights_dict)` | CLI 입력 또는 CSV 입력을 읽어서 분석 대상 포트폴리오를 표준 형태로 만든다. |
| `compute_feature_metrics()` | `dict` | 각 자산의 변동성, MDD, VaR/CVaR, beta, corr, stress 수익률, ADV, Sharpe proxy 등을 계산한다. |
| `build_asset_sensitivity_rows()` | `list[dict]` | 자산별 민감도 방향, 강도, 구조 태그를 만들어 “어떤 리스크에 민감한 자산인지” 설명 가능한 형태로 정리한다. |
| `compute_portfolio_returns()` | `(returns_list, error_message)` | 여러 자산의 비중을 반영해 포트폴리오 수익률 시계열을 계산한다. 실패 시 에러 메시지를 함께 돌려준다. |
| `build_candidate_prefilter_rows()` | `list[dict]` | 후보 자산별 HES 구성요소를 계산해서 1차 후보 랭킹 테이블을 만든다. |
| `choose_candidate_pool()` | `list[dict]` | prefilter 결과에서 실제 추천 평가에 사용할 후보군을 고른다. |
| `evaluate_gate()` | `dict` | CVaR, MDD, stress, 노출 개선, 유동성 조건 등을 기준으로 추천안이 `PASS`인지 판정한다. |
| `evaluate_recommendations()` | `dict` | 단일 자산/포트폴리오 기준으로 1:1 추천안과 멀티 추천안을 평가하고 최종 비교 결과를 만든다. |
| `write_result_documents()` | `(result_md, draft_md, review_md)` | 실행 결과, 분석 초안, 결과 검토 문서를 Markdown으로 생성한다. |
| `main()` | `None` | 전체 파이프라인의 진입점이다. 데이터 로드, 지표 계산, 후보 평가, 산출물 저장까지 전체 흐름을 실행한다. |

## 4. 대시보드 서버 주요 함수

대상 파일: `scripts/serve_dashboard.py`

| 함수 | 리턴값 | 역할 |
|---|---|---|
| `resolve_asset_query()` | `str` | 사용자가 입력한 회사명/자산명/티커를 실제 분석용 ticker로 변환한다. 모호하면 에러를 낸다. |
| `parse_portfolio_text()` | `list[dict]` | 웹에서 받은 포트폴리오 텍스트를 `{ticker, weight_pct}` 형태로 변환한다. |
| `parse_summary_markdown()` | `(meta_dict, next_actions_list)` | 실행 결과 Markdown에서 메타 정보와 다음 액션 항목을 추출한다. |
| `prepare_run_request()` | `dict` | 분석 요청을 표준 실행 요청으로 정리하고, 필요한 임시 입력 파일과 실행 명령을 준비한다. |
| `launch_run_job()` | `dict` | 백그라운드 분석 작업을 시작하고 현재 작업 상태를 반환한다. |
| `run_pipeline_for_request()` | `dict` | 준비된 요청을 기준으로 파이프라인을 실제 실행하고 `runId`와 실행 결과를 돌려준다. |
| `choose_best_detail()` | `dict \| None` | 비교표와 상세 추천 데이터를 연결해서 “가장 보여줄 가치가 큰 추천안” 1개를 골라낸다. |
| `load_dashboard_data()` | `dict` | CSV/Markdown 산출물을 읽어서 대시보드 화면에 바로 쓸 수 있는 JSON payload로 정리한다. |
| `main()` | `None` | 로컬 HTTP 서버를 띄우고 대시보드 API와 정적 파일 제공을 시작한다. |

## 5. 웹 UI 주요 함수

대상 파일: `web/app.js`

| 함수 | 리턴값 | 역할 |
|---|---|---|
| `fetchJson()` | `Promise<object>` | 서버 API에서 JSON을 가져오는 공통 함수이다. |
| `collectPortfolioRows()` | `Array<{ asset, amountKrw }>` | 화면에 입력된 포트폴리오 행들을 읽어서 분석 요청용 데이터로 만든다. |
| `renderOverview()` | `void` | 실행 시각, 기준 자산, DQ 요약 같은 상단 개요 정보를 렌더링한다. |
| `renderCompareSection()` | `void` | 기존 포지션 vs 추천 포지션의 리스크 비교표를 그린다. |
| `renderAllocation()` | `void` | 추천안의 자산 비중과 배분 스냅샷을 화면에 보여준다. |
| `renderSensitivitySection()` | `void` | 자산별 민감도, 방향, 강도 정보를 카드/배지 형태로 보여준다. |
| `loadDashboard()` | `Promise<void>` | 서버에서 최신 대시보드 데이터를 받아 전체 화면을 다시 렌더링한다. |
| `waitForRunJob()` | `Promise<object>` | 백그라운드 분석 작업이 끝날 때까지 상태를 폴링한다. |
| `runAnalysis()` | `Promise<void>` | 사용자가 입력한 조건으로 분석을 실행하고, 완료 후 대시보드를 새로고침한다. |
| `bootstrap()` | `Promise<void>` | 첫 페이지 로딩 시 run 목록, 자산 목록, 초기 화면을 세팅한다. |

## 6. 가장 먼저 보면 좋은 함수 5개

프로젝트를 처음 읽는다면 아래 5개를 먼저 보는 것이 가장 효율적이다.

1. `scripts/run_data_pipeline.py`의 `main()`
2. `scripts/run_data_pipeline.py`의 `evaluate_recommendations()`
3. `scripts/run_data_pipeline.py`의 `build_candidate_prefilter_rows()`
4. `scripts/serve_dashboard.py`의 `load_dashboard_data()`
5. `web/app.js`의 `runAnalysis()`

이 5개만 먼저 읽어도
“입력 → 계산 → 추천 → 결과 출력 → UI 표시” 흐름을 거의 파악할 수 있다.
