# HedgeMate 현업형 헷지 규칙 v1 요구사항 문서

- 작성일: 2026-03-10
- 기준 상태: Step1 데이터 파이프라인 완료본(data_version 20260305) 기반
- 목적: HedgeMate를 단순 배치 분석에서 **KRW 기준의 실사용형 헷지 추천 엔진**으로 고도화하기 위한 구현 요구사항 확정

---

## 1. 배경 및 목표
현재 HedgeMate는 아래 흐름을 수행할 수 있다.
- 70개 유니버스 데이터 수집
- 리스크 지표 계산(CVaR, MDD, 변동성, 상관 등)
- HES 기반 헷지 후보 랭킹
- 포트폴리오 개선 효과 비교

다음 단계 목표는 다음과 같다.
1. 모든 추천을 **KRW(원화) 기준**으로 일관되게 평가한다.
2. **Sharpe 지수**를 보조지표로 반영한다.
3. 채권/금/원자재/방어섹터/암호화폐를 포함한 **멀티자산 헷지 후보군**을 운영한다.
4. 단일 종목 질의(예: `TSLA`)에 대해 **1~4개 자산 조합 헷지 추천**이 가능하도록 한다.
5. 추천 로직을 **CVaR/MDD 중심의 현업형 통과 규칙 + 복합 점수식**으로 재정의한다.

## 2. 확정 의사결정

### 2.1 기준통화
- 공식 기준통화는 **KRW**로 고정한다.
- 모든 성과/리스크 비교는 **한국 투자자 기준 원화 손익** 관점으로 해석한다.

### 2.2 환율 처리 규칙
- USD 표시 자산(미국주식, 미국 ETF, 금 ETF, 채권 ETF, 원자재 ETF, 암호화폐)은 **일별 USD/KRW 환율을 적용해 KRW 기준 가격/수익률 시계열**로 변환 후 사용한다.
- KRW 자산은 환산 없이 그대로 사용한다.
- 모든 return-based 지표(변동성, MDD, VaR/CVaR, beta, corr, stress 성과, Sharpe)는 **KRW 기준 수익률 시계열**로 계산한다.

### 2.3 Sharpe 반영 원칙
- Sharpe는 **반드시 반영**한다.
- 단, **1차 통과조건이 아닌 보조지표**로 사용한다.
- 추천 자격은 CVaR/MDD/Stress/상관·beta/유동성이 먼저 결정한다.
- Sharpe는 통과 후보 간 **2차 점수 차별화**에 사용한다.

### 2.4 Sharpe 계산 방식 (MVP)
- MVP에서는 `sharpe_1y_krw_proxy`를 사용한다.
- 정의:
  - `annual_return_1y_krw = KRW 기준 최근 1년 누적수익률의 연환산값`
  - `vol_annual_krw = KRW 기준 연환산 변동성`
  - `sharpe_1y_krw_proxy = (annual_return_1y_krw - rf) / vol_annual_krw`
- MVP의 무위험수익률은 **연 3% 고정값**으로 시작한다.
- 차기 단계에서 KRW 단기금리(예: 3개월 국채/통안채)로 교체 가능하도록 확장 여지를 둔다.

- `XLP`, `XLU`, `XLV`

### 3.2 운영 원칙
- 위 후보군은 **헷지 전용 탐색 후보군**으로 사용한다.
- 암호화폐도 포함하되, 다른 자산군보다 자동 우대하지 않는다.
- 모든 후보는 동일하게 DQ, 유동성, tail-risk 기준을 통과해야 한다.

## 4. 질의/분석 모드 정의

### 4.1 포트폴리오 입력 모드
- 기존 `inputs/portfolio_weights.csv` 기반 분석을 유지한다.
- 기존 입력 제약은 유지한다.
  - 비중 합계 100%
  - 음수 비중 금지
  - 포트폴리오 입력 단일 자산 최대 50%
  - 위 cap은 **사용자 입력 포트폴리오에만 적용**한다.

### 4.2 단일 종목 질의 모드
예: `TSLA`, `AAPL`, `005930.KS`

- 질의 자산 1개를 **기준 포트폴리오 100%**로 본다.
- 그 위에 헷지 자산을 추가한 뒤 리스크 완화 효과를 계산한다.
- 이 모드는 일반 포트폴리오 모드와 별도로 동작한다.

### 4.3 단일 종목 질의 모드 기본 규칙
- 기준 포트폴리오: `질의자산 100%`
- 웹 UI/API의 기본 예산 입력은 **KRW 우선**
- `% 예산 시나리오`는 보조/고급 옵션으로 유지
- 추천 조합 크기: `1개`, `2개`, `3개`, `4개`
- 헷지 자산 1개당 최대 비중: 기본 `20%`
- 자기 자신 중복 추천 금지
  - 예: `TSLA + TSLA` 금지
- 사용자-facing 입력은 **회사명/자산명/티커 허용(유일 매칭 기준)** 으로 운영한다.

## 5. 조합 탐색 규칙

### 5.1 조합 다양성 규칙
조합 추천이 특정 자산군에 과도하게 쏠리지 않도록 아래 제약을 둔다.
- 조합 크기 2개 이상이면 **최소 2개 자산군 포함**
- 동일 자산군은 **최대 2개 자산까지만 허용**
- 암호화폐는 **조합당 최대 1개** 권장

### 5.2 조합 탐색 성능 규칙
1. 자산군별 1차 후보를 선별한다.
2. 선별된 축소 후보군에서 1~4개 조합을 탐색한다.
3. 전수탐색 대신 **후보 사전 압축 후 평가** 방식으로 계산량을 통제한다.

### 5.3 권장 탐색 절차
- Step A: 자산군별 단일자산 예비점수 계산
- Step B: 자산군별 상위 K개 선별
- Step C: 축소 후보군으로 조합 생성
- Step D: 통과조건 필터링
- Step E: 복합 점수로 최종 랭킹

## 7. 추천 통과 규칙 (필수)
아래 조건을 모두 만족한 후보만 추천 대상으로 인정한다.

1. `CVaR 개선 > 0`
2. `MDD 개선 >= 0`
3. `Stress 평균수익률 개선 >= 0`
4. `상관 또는 beta 감소`
5. `유동성 기준 통과`
6. `DQ FAIL 자산 제외`

보조지표인 Sharpe는 위 통과조건을 대체할 수 없다.
즉, **Sharpe가 좋아도 CVaR/MDD가 나빠지면 탈락**한다.

추천 0건 fallback 정책:
- Gate 통과 후보가 0건이면 **최종 점수 기준 참고안**을 함께 제공한다.
- 이 경우 사용자에게 `리스크 관리가 어렵습니다` 경고 메시지를 함께 노출한다.

데이터 부족 처리 원칙:
- 데이터 부족 자산도 **추천 계산까지는 허용**한다.
- 단, Gate 필수 지표가 결측이면 PASS 추천으로 승격하지 않는다.

## 8. 최종 점수식 (v1)
통과 후보를 대상으로 아래 복합 점수식을 사용한다.

- **35%** CVaR 개선
- **20%** MDD 개선
- **20%** Stress 방어
- **10%** 상관/베타 감소
- **10%** Sharpe 개선
- **5%** 유동성 점수

### 8.1 해석 원칙
- 점수식의 철학은 **“꼬리손실 방어 우선, 효율성은 보조”** 이다.
- CVaR/MDD/Stress가 핵심이며, Sharpe는 최종 추천 품질을 보완한다.

## 10. 수용 기준 (Acceptance Criteria)
1. 모든 비교 지표가 **KRW 기준**으로 일관되게 계산된다.
2. `features_summary`에 `annual_return_1y_krw`, `sharpe_1y_krw_proxy`가 추가된다.
3. 포트폴리오 비교 산출물에 `base_sharpe_krw_proxy`, `proposed_sharpe_krw_proxy`, `sharpe_improve_pct`가 추가된다.
4. 단일 종목 질의(예: `TSLA`)에 대해 1개~4개 조합 추천이 가능하다.
5. 추천 결과는 반드시 `CVaR 개선 > 0`, `MDD 개선 >= 0`를 만족한다.
6. 암호화폐가 후보군에 포함되더라도 tail-risk 기준을 통과하지 못하면 자동 제외된다.
7. 추천 리포트에서 사용자는 **“왜 이 조합이 추천되었는지”**를 정량 지표 기준으로 확인할 수 있다.
8. 포트폴리오 입력 모드는 `합계 100%`, `음수 금지`, `개별 종목 <= 50%`를 만족해야 한다.
9. 사용자-facing 종목 입력은 회사명/자산명/티커를 허용하되, 복수 매칭 시 자동 실행하지 않는다.
10. 사용자-facing 후보 리스트는 **최대 10개**까지 노출한다.

## 11. 비범위(Out of Scope, v1 제외)
아래는 v1 범위에서 제외한다.
- 옵션 기반 protective put / collar 직접 구현
- 선물 기반 beta hedge 직접 구현
- FX overlay 동적 헷지 고도화
- 금리 DV01/duration hedge 직접 구현
- 실시간 API/챗 인터페이스 배포

v1은 위 현업 기법의 **원리(노출 완화, tail-risk 우선, 멀티자산 조합)** 를 현재 데이터 범위 안에서 구현하는 단계로 정의한다.

## 13. 예시 질의 목표
사용자가 다음과 같이 질문했을 때:
- `TSLA 헷지 뭐가 좋음?`
- `엔비디아 리스크 줄이는 조합 추천해줘`
- `내 포트폴리오에 방어자산 2~4개 섞어서 개선안 보여줘`

시스템은 아래를 반환할 수 있어야 한다.
- 단일 헷지 후보 Top N
- 2~4자산 조합 Top N
- 각 후보별 CVaR/MDD/Stress/Beta(or Corr)/Sharpe 변화량
- 추천 이유 요약

## 14. 요약
본 요구사항 문서는 HedgeMate를 **KRW 기준 멀티자산 헷지 추천 엔진**으로 확장하기 위한 v1 기준안이다.
핵심 철학은 다음과 같다.

- **원화 기준으로 본다**
- **꼬리손실과 낙폭 방어를 우선한다**
- **Sharpe는 보조지표로 반영한다**
- **채권/금/원자재/방어섹터/암호화폐를 포함한 1~4개 조합 추천을 지원한다**
- **현업형 헷지 원칙을 현재 데이터 범위에서 구현 가능한 수준으로 번역한다**
