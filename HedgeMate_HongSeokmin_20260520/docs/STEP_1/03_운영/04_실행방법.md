# 데이터 파이프라인 실행방법 (KRW 헷지엔진 v1)

## 1) 기본 실행 명령
```bash
python3 scripts/run_data_pipeline.py
```

> 현재는 **수동 실행만 지원**하며, 자동 라이브 데이터 갱신/스케줄링은 적용하지 않는다.

> 참고: 실행일 기준 raw 스냅샷이 없고 최신 캐시가 존재하면, 파이프라인은 **가장 최근 cached snapshot을 재사용**해 최신 산출물 생성을 계속 진행한다.

## 1-1) 웹 UI 실행 명령
```bash
python3 scripts/serve_dashboard.py --port 8080
```
- 접속 주소: `http://127.0.0.1:8080`
- 현재 UI는 **최신 생성 산출물 시각화 + 수동 분석 실행**을 지원하며, 실시간 자동 갱신은 지원하지 않는다.

## 2) 단일 종목 질의 모드 예시
```bash
python3 scripts/run_data_pipeline.py --single-asset TSLA --hedge-budgets 10,20,30 --max-combo-size 4
```

## 3) 옵션
- `--single-asset <TICKER>`
  - 단일 종목 질의 모드 실행
  - CLI에서는 **ticker 입력 권장**
- `--hedge-budgets 10,20,30`
  - 헷지 예산 시나리오(%)
- `--max-combo-size 4`
  - 추천 최대 조합 크기 (`1~4`)
- `--candidate-mode hedge-only|all`
  - 기본은 `hedge-only`
  - `all`은 전체 유니버스 탐색

> 주의: 외부 시세 API(Yahoo Finance) 접근이 필요함.

---

## 4) 입력 파일
- 유니버스 메타: `docs/STEP_1/01_개요/03_자산유니버스_메타_v1.csv`
- (선택) 사용자 포트폴리오 입력: `inputs/portfolio_weights.csv`
  - 없으면 `outputs/reports/portfolio_input_sample.csv` 자동 생성/사용
  - 컬럼: `ticker`, `weight_pct`

웹 UI 입력:
- 단일 자산 입력: **회사명/자산명/티커 허용(유일 매칭 기준)**
- 포트폴리오 입력: UI에서는 **회사명/자산명 기반 입력 + KRW 금액 입력** 지원
- UI는 실행 시 최신 결과 스냅샷을 다시 읽어 갱신

포트폴리오 입력 제약:
- 비중 합계 100%
- 음수 비중 금지
- 포트폴리오 입력 단일 자산 최대 50%

단일 종목 질의 모드 제약:
- 기준 종목 100%로 해석
- 헷지 자산 1개당 최대 20%
- 자기 자신 중복 추천 금지
- FX 환산은 exact match 우선, 없으면 최대 7일 carry-forward
- 웹 UI/API는 KRW 예산 입력을 우선 사용한다.

## 6) 검토 포인트
1. DQ PASS/WARN/FAIL 비율 및 `coverage_ratio_calendar`
2. FX raw 생성 여부 및 USD 자산 KRW 환산 적용 여부
3. benchmark raw 생성 여부 및 `^KS200/^KS11` 재현성 확보 여부
4. `metric_validation` PASS 여부
5. HES Top10 구성요소(Corr/CVaR/Stress/Sharpe/Liquidity) 해석 가능성
6. 추천 결과가 Gate 조건(CVaR/MDD/Stress/beta·corr/유동성)을 통과했는지
7. 기존 vs 제안 포트폴리오의 CVaR/MDD/Sharpe 개선률
8. 단일 종목 질의 결과의 1~4개 조합 추천 품질
9. Gate 통과 후보가 0건일 때 참고안 + 경고 메시지가 함께 나오는지
10. UI에서 티커 대신 자산/기업명이 사용자 친화적으로 표시되는지
11. 추천 조합의 자산배분(weights snapshot)이 시각적으로 노출되는지
12. 자산 민감도 산출물에서 factor별 direction / magnitude / sensitivity level(민감도 강도)가 저장되는지

---

## 7) 재현성 확인 방법
1. 같은 날짜에 2회 실행
2. `hes_components_YYYYMMDD.csv`의 Top-N 순서/점수 비교
3. 동일 `data_version`에서 결과가 동일하면 재현성 PASS
4. FX raw까지 동일 data_version으로 재사용되는지 확인
5. benchmark raw까지 동일 data_version으로 재사용되는지 확인

---

## 8) 왜 CSV를 유지하나? (v1)
- 사람이 바로 검토 가능(엑셀/시트)
- 학습 난이도가 낮아 디버깅/검증이 빠름
- 현재 규모(70개 자산, 일봉 5년, 1~4개 조합 추천)에서 운영 가능
