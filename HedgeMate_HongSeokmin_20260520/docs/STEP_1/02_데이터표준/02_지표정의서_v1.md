# HedgeMate 지표 정의서 v1.1 (KRW 헷지엔진 반영)

## 0) 공통 기준
- 데이터 주기: 일봉
- 분석 기간: 기본 5년, 데이터 부족 시 가용 구간 기준 계산 허용
- 기준통화: **KRW**
- 수익률 기준: 단순수익률(daily simple return)
- 위기구간 벤치마크: `SPY` + `^KS200`(fallback `^KS11`)
- USD 자산은 `KRW=X`로 환산 후 KRW 기준 수익률 계산

---

## 1) 기본 수익률
- 일간 수익률:
  - `ret_1d(t) = price_krw(t) / price_krw(t-1) - 1`
- USD 자산:
  - `price_krw(t) = adj_close_usd(t) * usdkrw(t)`
- KRW 자산:
  - `price_krw(t) = adj_close_krw(t)`

---

## 2) 변동성
- 연환산 변동성(일봉):
  - `vol_annual_krw = std(ret_1d_krw) * sqrt(252)`
- 결측 정책: 수익률 관측치 < 20이면 결측

---

## 3) 최대낙폭(MDD)
- 누적자산가치:
  - `equity(t) = Π(1 + ret_1d_krw)`
- 낙폭:
  - `drawdown(t) = equity(t)/max(equity(1..t)) - 1`
- 최대낙폭:
  - `MDD = min(drawdown)`
- 결측 정책: 가격 관측치 < 20이면 결측

---

## 4) VaR / CVaR (Historical, 95%)
- `VaR_95 = percentile(ret_1d_krw, 5%)`
- `CVaR_95 = mean(ret_1d_krw | ret_1d_krw <= VaR_95)`
- 결측 정책: 수익률 관측치 < 60이면 결측

---

## 5) 베타 / 하방 베타
- 일반 베타:
  - `beta = cov(ret_asset_krw, ret_spy_krw) / var(ret_spy_krw)`
- 하방 베타(시장 하락일):
  - `downside_beta = cov(ret_asset_krw, ret_spy_krw | ret_spy_krw < 0) / var(ret_spy_krw | ret_spy_krw < 0)`
- 결측 정책:
  - beta: SPY 교집합 수익률 < 60이면 결측
  - downside beta: 하락일 교집합 < 20이면 결측

---

## 6) 롤링 상관
- 60일 롤링 상관:
  - `corr_sp500_60d_krw`
  - `corr_kospi200_60d_krw`
- 계산은 벤치마크와의 교집합 날짜 기준
- 결측 정책: 교집합 관측치 < 20이면 결측

---

## 7) 위기구간 라벨
- `is_stress(t) = true` if
  - SPY 20거래일 KRW 수익률 <= -8% 또는
  - KOSPI200(`^KS200`, fallback `^KS11`) 20거래일 수익률 <= -8%

---

## 8) ADV(유동성) 지표
- 정의: `adv_60 = mean(price_krw * volume, 최근 60거래일)`
- 결측 정책: 유효 관측치 < 20이면 결측

---

## 9) 연환산 수익률 / Sharpe proxy
- 연환산 수익률:
  - `annual_return_1y_krw = (Π(1 + ret_1d_krw))^(252/N) - 1`
- Sharpe proxy (MVP):
  - `sharpe_1y_krw_proxy = annual_return_1y_krw / vol_annual_krw`
- MVP 가정:
  - 무위험수익률 `rf = 연 3%`
- 차기 단계:
  - KRW 3개월 국채/통안채 등 실데이터 연결 가능

---

## 10) 자산 예비 랭킹(HES, KRW 기준)
자산군별 후보 사전 압축용 점수.

`HES = 0.25*CorrImprovement + 0.25*CVaRQuality + 0.20*StressDefense + 0.15*SharpeQuality - 0.15*LiquidityPenalty`

### 구성요소
- `CorrImprovement`: `-corr_sp500_60d_krw` 정규화
- `CVaRQuality`: `cvar_95_1y_krw` 정규화 (덜 나쁠수록 우수)
- `StressDefense`: `avg_stress_ret_krw` 정규화
- `SharpeQuality`: `sharpe_1y_krw_proxy` 정규화
- `LiquidityPenalty`: `1 - norm(adv_60)`

### 정규화/클리핑 정책
- min-max 정규화 사용
- 평탄 분포(vmin==vmax)는 0.5 처리
- 최종 구성요소는 `[0,1]`로 클리핑
- 동점 정렬: `hes_score` 내림차순 후 `ticker` 오름차순

---

## 11) 최종 추천 통과 규칙 (Gate)
추천 후보는 아래 조건을 모두 만족해야 한다.
1. `CVaR 개선 > 0`
2. `MDD 개선 >= 0`
3. `Stress 평균수익률 개선 >= 0`
4. `상관 또는 beta 감소`
5. `유동성 기준 통과`
6. `DQ FAIL 제외`

> Sharpe는 **보조지표**이며 Gate를 대체할 수 없다.

---

## 12) 최종 추천 점수식 (Final Score)
Gate 통과 후보에 한해 아래 복합 점수를 적용한다.
- **35%** CVaR 개선
- **20%** MDD 개선
- **20%** Stress 방어
- **10%** 상관/베타 감소
- **10%** Sharpe 개선
- **5%** 유동성 점수

해석 원칙:
- **꼬리손실 방어 우선, 효율성은 보조**
- CVaR/MDD/Stress가 핵심
- Sharpe는 최종 추천 품질 차별화에 사용

---

## 13) 단일 종목 질의 모드
예: `TSLA`
- CLI 입력 계약: **ticker 허용**
- UI/API 입력 계약: **회사명/자산명/티커 허용(유일 매칭 기준)**
- 기준 포트폴리오: `TSLA 100%`
- 기본 예산 입력: **KRW 우선**
- `% 예산`은 보조 시나리오로 유지
- 추천 조합 크기: `1~4개`
- 헷지 자산 1개당 최대 비중: 기본 `20%`
- 자기 자신 중복 추천 금지

조합 다양성 규칙:
- 조합 크기 2개 이상이면 최소 2개 자산군 포함
- 동일 자산군 최대 2개
- 암호화폐 조합당 최대 1개 권장

추천 0건 fallback:
- Gate 통과 후보가 0건이면 **최종 점수 기준 참고안**을 함께 표시
- 이 경우 경고 메시지: `Gate 통과 후보가 없어 참고안을 표시합니다. 리스크 관리가 어렵습니다.`
