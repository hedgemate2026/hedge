# HedgeMate 데이터 스펙 v1.1 (KRW 헷지엔진 반영)

## 0. 목적
`docs/STEP_1/01_개요/02_자산유니버스_v1.md` 기준 유니버스를 대상으로,
HedgeMate의 데이터 수집/정제/분석/헷지 추천에 필요한 **데이터 소스, 공통 스키마, 품질 규칙, KRW 환산 규칙**을 고정한다.

---

## 1. 데이터 소스 정의

### 1.1 가격/거래량 (일봉)
- **Primary**: Yahoo Finance (chart API)
  - 대상: 한국/미국 개별주, ETF, 채권 ETF, 금/원자재 ETF, 암호화폐
  - 티커 예시: `005930.KS`, `AAPL`, `SPY`, `GLD`, `BTC-USD`

### 1.2 FX (일봉)
- **Primary**: Yahoo Finance (`KRW=X`)
- 용도: USD 표시 자산을 **KRW 기준 가격/수익률 시계열**로 환산

### 1.3 소스 운영 원칙
- MVP는 **Yahoo 중심**으로 운영
- 소스 변경/보완 시 `data_version` 변경 이력 기록
- FX는 **exact date match 우선**, 없으면 **최대 7일 carry-forward** 사용

### 1.4 출력 포맷 표준
- 공식 산출 포맷은 **CSV 고정**
- 산출 경로:
  - `outputs/raw`
  - `outputs/processed`
  - `outputs/reports`

## 3. 기준통화 및 환산 규칙
- 공식 기준통화는 **KRW**
- USD 자산은 **일별 USD/KRW 환율 적용 후 KRW 가격/수익률**로 계산
- KRW 자산은 환산 없이 그대로 사용
- 모든 return-based metric은 KRW 기준 계산
  - 변동성
  - MDD
  - VaR/CVaR
  - beta / downside beta
  - corr
  - stress 성과
  - Sharpe proxy

---

## 4. 위기구간(Stress) 라벨 정의
- 라벨 규칙:
  - `SPY` 또는 `^KS200`(부재 시 `^KS11`)의 **20거래일 수익률 <= -8%** 이면 stress
- 판정 단위: 일봉 날짜별 Boolean
- KRW 기준 평가 단계에서는 **SPY KRW 수익률**을 사용

## 5. 데이터 품질 규칙 (DQ Rules)

### 5.1 필수 검증
1. PK 중복 없음: `(date, ticker)` 중복 0건
2. 가격 무결성: `high >= low`, `open/close > 0`
3. 결측률(`missing_rate`)
   - PASS: < 1%
   - WARN: 1% ~ 5%
   - FAIL: > 5%
4. 캘린더 커버리지(`coverage_ratio_calendar`)
   - 계산: `rows / expected_rows_calendar`
   - calendar_type:
     - `US_WEEKDAY` (US/GLOBAL)
     - `KR_WEEKDAY` (KR)
     - `CRYPTO_24_7` (CRYPTO)
   - PASS: >= 0.97
   - WARN: 0.90 ~ 0.97 미만
   - FAIL: < 0.90
5. 이상치(일수익률)
   - 주식/ETF/채권/원자재: `|ret_1d| > 40%`
   - 암호화폐: `|ret_1d| > 60%`
6. FX 매칭 실패 수(`fx_missing_count`) 기록

### 5.2 처리 정책
- WARN: 분석 포함 가능, 리포트 경고 노출
- FAIL: 추천 후보 기본 제외(원인 확인 후 재수집/대체 검토)
- 이상치: 자동 삭제 금지, 원천 이벤트 확인 후 처리
- FX 미매칭: 제한된 carry-forward 이후에도 없으면 해당 일자 metric 계산 제외
- 데이터 부족: 가용 구간 기준 계산은 허용한다. 단, Gate 필수 지표가 결측이면 PASS 추천으로 승격하지 않는다.

## 6. 분석 입력 계약 (Portfolio I/O)

### 6.1 포트폴리오 입력 모드
- 기본 파일: `inputs/portfolio_weights.csv` (없으면 샘플 자동생성)
- 샘플 파일: `outputs/reports/portfolio_input_sample.csv`
- 컬럼: `ticker`, `weight_pct`

### 6.2 입력 제약
- 비중 합계 100%
- 음수 비중 금지
- 포트폴리오 입력 모드에서 단일 자산 최대 50%
- 생성 추천 조합의 cap 규칙은 별도 추천 제약을 따른다.

### 6.3 단일 종목 질의 모드
- 입력 예시: `TSLA`
- CLI 입력 계약: **ticker 허용**
- UI/API 입력 계약: **회사명/자산명/티커 허용(유일 매칭 기준)**
- 기준 포트폴리오: **단일 자산 100%**
- 기본 예산 입력: **KRW 우선**
- `% 예산 시나리오`는 보조/고급 옵션으로 유지
- 추천 조합 크기: `1개`, `2개`, `3개`, `4개`
- 헷지 자산 1개당 최대 비중: 기본 `20%`

## 7. 출력 산출물
- Raw 시장데이터: `outputs/raw/raw_market_daily_YYYYMMDD.csv`
- Raw FX: `outputs/raw/raw_fx_daily_YYYYMMDD.csv`
- Raw Benchmark: `outputs/raw/raw_benchmark_daily_YYYYMMDD.csv`
- DQ 결과: `outputs/reports/dq_result_YYYYMMDD.csv`
- 지표 요약: `outputs/processed/features_summary_YYYYMMDD.csv`
- 자산 민감도 CSV: `outputs/processed/asset_risk_sensitivity_YYYYMMDD.csv`
- 지표 검증셋: `outputs/reports/metric_validation_YYYYMMDD.csv`
- 헷지 후보/HES 구성요소: `outputs/reports/hes_components_YYYYMMDD.csv`
- 자산 민감도 요약: `outputs/reports/asset_sensitivity_summary_YYYYMMDD.md`
- 포트폴리오 1:1: `outputs/reports/portfolio_1to1_hedge_YYYYMMDD.csv`
- 포트폴리오 다자산: `outputs/reports/portfolio_multi_hedge_YYYYMMDD.csv`
- 포트폴리오 비교: `outputs/reports/portfolio_compare_YYYYMMDD.csv`
- 단일자산 1:1: `outputs/reports/single_asset_hedge_1to1_YYYYMMDD.csv`
- 단일자산 다자산: `outputs/reports/single_asset_hedge_multi_YYYYMMDD.csv`
- 단일자산 비교: `outputs/reports/single_asset_compare_YYYYMMDD.csv`

추천 0건 처리 정책:
- Gate 통과 후보가 0건이면 **참고안 1건 이상**을 함께 제공
- 이 경우 `no_recommendation_reason`에 경고 메시지를 기록
