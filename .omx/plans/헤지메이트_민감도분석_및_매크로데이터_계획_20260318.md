# 헤지메이트 민감도분석 및 매크로데이터 확장 계획 (2026-03-18)

## 1. 목적
HedgeMate의 다음 단계는 추천 엔진 개편 전에 다음 두 가지를 먼저 고정하는 것이다.

1. **자산 민감도 분석 기준**  
   - 입력 자산이 무엇에 민감한지 정량적으로 분류
   - 단순 변동성뿐 아니라 **방향(direction)과 크기(magnitude)** 를 함께 기록
2. **민감도 분석에 필요한 매크로데이터 수집 체계**  
   - FX / 금리 / 인플레이션을 정형 시계열로 수집해 민감도 판정 근거로 사용

추가로, 사용자가 요청한 대로  
**“어떤 것들로 민감도 분석했는지”를 MD 파일로 남기는 것**을 본 계획의 필수 산출물로 포함한다.

---

## 2. 현재 기준선 (repo evidence)
- 현재 수집/저장 중인 raw 데이터
  - `outputs/raw/raw_market_daily_YYYYMMDD.csv`
  - `outputs/raw/raw_fx_daily_YYYYMMDD.csv`
  - `outputs/raw/raw_benchmark_daily_YYYYMMDD.csv`
- 현재 계산 중인 핵심 feature
  - `beta_sp500_1y_krw`
  - `downside_beta_sp500_1y_krw`
  - `corr_sp500_60d_krw`
  - `corr_kospi200_60d_krw`
  - `avg_stress_ret_krw`
  - `cvar_95_1y_krw`
  - `mdd_1y_krw`
  - `annual_return_1y_krw`
  - `sharpe_1y_krw_proxy`
- 현재 macro 측면에서 직접 수집 중인 것은 사실상 `KRW=X` FX뿐이다.
- 금리 / 인플레이션 / 지정학은 현재 **직접 시계열이 아니라 프록시 자산**으로만 간접 반영되고 있다.

즉 현재 상태는:
- **시장/하락장 민감도 분석은 가능**
- **FX/금리/인플레 민감도를 신뢰도 높게 분류하기엔 직접 factor data가 부족**

## 4. 공식 데이터 소스 전략

## Step 1. 수집할 매크로 팩터와 공식 소스를 고정
### 목표
신뢰 가능한 정형 데이터만 우선 수집해 민감도 분석에 투입할 source contract를 확정한다.

### 작업
- 아래 팩터를 v1 수집 대상으로 고정한다.
  1. **FX**
     - Primary: 기존 `KRW=X`
     - Validation/backup 후보: FRED `DEXKOUS`
  2. **미국 금리**
     - Primary: FRED (`DGS2`, `DGS10` 등)
  3. **한국 금리**
     - Primary: 한국은행 ECOS Open API
     - 대상 예: 기준금리, 국고채 3년/10년
  4. **미국 인플레이션**
     - Primary: FRED `CPIAUCSL`
  5. **한국 인플레이션**
     - Primary: KOSIS CPI
- 지정학은 v1에서 직접 수집하지 않고 보조 태그/차기 확장 항목으로 분리한다.
- 각 소스별 주기(일/월), 인증키 필요 여부, fallback 정책을 표로 정리한다.

### Acceptance Criteria
- 팩터별 공식 소스, 주기, fallback, 인증 요구사항이 한 문서에 표 형태로 정리된다.
- FX / 금리 / 인플레이션이 v1 직접 수집 대상으로 확정된다.
- 지정학 direct data 수집은 v1 비범위로 명시된다.

---

## Step 2. 매크로 데이터 저장 계약과 파이프라인 범위를 정의
### 목표
새로 수집할 macro data가 기존 raw/processed 구조와 충돌 없이 들어가도록 저장 계약을 고정한다.

### 작업
- 신규 raw 산출물 계약을 정의한다.
  - 예: `outputs/raw/raw_macro_daily_{run_id}.csv`
  - 예: `outputs/raw/raw_macro_monthly_{run_id}.csv`
- macro feature 정규화 컬럼 계약을 정의한다.
  - 예: `us10y_rate`, `us2y_rate`, `kr_base_rate`, `kr10y_rate`, `us_cpi_yoy`, `kr_cpi_yoy`
- 월간 데이터(CPI)의 일봉 엔진 반영 방식을 명시한다.
  - 발표월 값 유지
  - YoY 기반 사용
  - 일봉 시계열에는 forward-fill 허용 여부 명시
- 기존 `features_summary`에 직접 합칠지, 별도 macro/factor table을 둘지 구조를 정한다.

### Acceptance Criteria
- 신규 raw/processed macro 산출물 명세가 명확하다.
- 월간 CPI를 일봉 민감도 분석에 연결하는 규칙이 문서화된다.
- 후속 구현자가 파일명, 컬럼명, 주기 처리 방식을 추측하지 않아도 된다.

---

## Step 3. 민감도 taxonomy와 score 체계를 재구성
### 목표
기존 broad taxonomy를 현재/추가 수집 가능한 데이터에 맞게 재편한다.

### 작업
- v1 primary sensitivity taxonomy를 아래처럼 재구성한다.
  1. 글로벌 시장 하락 민감
  2. 하락장 꼬리손실 민감
  3. 한국시장 동행 민감
  4. **FX 민감**
  5. **금리 민감**
  6. **인플레이션 민감**
  7. 방어형/저민감 성향(혼합/예외 처리용)
- 지정학은 primary risk가 아니라 `structural_tag`로 둔다.
- 각 taxonomy별로 핵심 score와 증거 지표를 정의한다.
  - FX: 통화 노출 + FX factor 민감도
  - 금리: 금리 factor 변화와 자산 수익률 반응
  - 인플레: CPI proxy/factor와 자산 반응
- 각 taxonomy별로 아래 3요소를 함께 정의한다.
  1. **direction**: 해당 factor 상승/하락에 자산이 같은 방향인지 반대 방향인지
  2. **magnitude**: 반응 강도(민감도 계수 절대값 또는 정규화 강도)
  3. **confidence**: 표본 수/지표 일관성/판정 우위 폭
- `primary_risk`, `secondary_risks`, `confidence`, `structural_tags` 구조를 고정한다.
- factor별 결과 표현은 가능하면 아래 형태를 따른다.
  - 예: `rate_sensitivity_direction = negative`
  - 예: `rate_sensitivity_magnitude = 0.72`
  - 예: `rate_sensitivity_confidence = high`

### Acceptance Criteria
- FX/금리/인플레가 broad 설명 수준이 아니라 scoreable taxonomy로 정의된다.
- 각 taxonomy마다 direction / magnitude / confidence가 함께 정의된다.
- primary / secondary / confidence 구조가 명시된다.
- 지정학은 v1에서 tag 수준이라는 경계가 유지된다.

---

## Step 4. “민감도 분석 기준서(MD)”와 결과 산출물 계약을 정의
### 목표
사용자가 요청한 대로 “무엇으로 민감도 분석했는지”가 문서와 산출물에 남도록 한다.

### 작업
- 영구 문서 산출물로 다음 파일을 정의한다.
  - `docs/STEP_1/02_데이터표준/04_자산민감도_기준서_v1.md`
- 이 문서에 반드시 포함할 내용을 고정한다.
  1. 사용 팩터 목록(FX / 금리 / 인플레 / 시장 / stress)
  2. 각 팩터의 데이터 소스
  3. 민감도 score 수식/정규화 방식
  4. 각 팩터별 direction 판정 규칙
  5. 각 팩터별 magnitude 계산 규칙
  6. primary/secondary/confidence 판정 규칙
  7. fallback 및 데이터 부족 처리 규칙
- 실행 결과 산출물로는 다음을 권장한다.
  - `outputs/reports/asset_sensitivity_summary_{run_id}.md`
  - `outputs/processed/asset_risk_sensitivity_{run_id}.csv`
- 결과 MD에는 “이번 run에서 어떤 민감도 축을 사용했고 어떤 값으로 판정했는지”를 요약하게 한다.
- 결과 CSV/MD는 최소 아래 정보를 남기도록 한다.
  - `factor`
  - `direction`
  - `magnitude`
  - `confidence`
  - `evidence_metrics`

### Acceptance Criteria
- 민감도 분석 기준이 영구 MD 문서로 고정된다.
- run별로 어떤 기준으로 민감도 분석했는지 추적 가능한 MD/CSV 산출물 계약이 정의된다.
- run별 산출물에서 factor별 direction / magnitude / confidence를 확인할 수 있다.
- “분석 기준이 코드에만 숨어 있는 상태”를 벗어난다.

---

## Step 5. 대표 자산 검증셋과 테스트 계획을 고정
### 목표
새로운 민감도 체계가 상식적으로 동작하는지 검증 가능한 기준을 만든다.

### 작업
- 대표 검증셋을 고정한다.
  - 미국 성장주: `TSLA`, `NVDA`
  - 한국 대형주: `005930.KS`
  - 금: `GLD`
  - 채권: `IEF`, `TLT`, `SHY`
  - 인플레/원자재: `TIP`, `DBC`, `USO`
  - 방어섹터: `XLU`, `XLP`
  - 암호화폐: `BTC-USD`
- 각 자산에 대해 “기대 민감도 프로파일”을 정의한다.
  - 예: TSLA → 글로벌 하락 민감 `direction=positive`, `magnitude=high`
  - 예: GLD → 인플레 민감 `direction=positive`, 방어 성향 `magnitude=medium/high`
  - 예: SHY → 금리 민감 `direction=negative 또는 저민감`, 방어 성향 `magnitude=high`
- 테스트 층을 나눈다.
  1. raw macro 수집 테스트
  2. factor join 테스트
  3. sensitivity score + direction/magnitude 계산 테스트
  4. 대표 자산 sanity check 테스트

### Acceptance Criteria
- 최소 8개 이상 대표 자산의 기대 민감도 프로파일이 문서화된다.
- 수집/정규화/score/direction/magnitude/결과 산출 각 층의 테스트 포인트가 정해진다.
- 후속 executor가 테스트 작성 기준을 바로 알 수 있다.

## Step 6. 구현 handoff와 단계별 실행 순서를 확정
### 목표
이 계획이 바로 구현 가능한 작업 단위로 이어질 수 있게 handoff한다.

### 작업
- 구현 lane을 다음처럼 분리한다.
  1. **데이터 lane**
     - macro raw 수집
     - 주기 정규화
  2. **분석 lane**
     - sensitivity score 계산
     - direction / magnitude 계산
     - confidence 판정
  3. **문서/리포트 lane**
     - `자산민감도_기준서_v1.md`
     - run별 sensitivity summary md
- 권장 실행 순서를 명시한다.
  1. source contract 고정
  2. raw macro 저장 계약 구현
  3. factor join / feature 확장
  4. sensitivity score + direction/magnitude 구현
  5. md/summary/report 산출
  6. 대표 자산 sanity check
- 비범위를 다시 고정한다.
  - 추천엔진 개편 금지
  - 지정학 direct ingestion 금지
  - 뉴스/비정형 파싱 금지

### Acceptance Criteria
- 후속 planner/architect/executor가 역할별로 바로 이어받을 수 있다.
- 구현 순서가 명확해 병렬/순차 작업 구분이 가능하다.
- scope creep 방지선이 문서에 남는다.

## 8. 검증 방법

## 9. Planner Handoff Note
이 계획은 단순히 데이터를 더 모으는 계획이 아니라,
**“HedgeMate가 왜 이 자산을 이런 리스크에 민감하다고 봤는지”를 정형 데이터와 문서로 설명 가능하게 만드는 계획**이다.

핵심 원칙:
- 비정형보다 정형 우선
- FX / 금리 / 인플레 우선
- 지정학은 보조 태그
- 민감도 분석 기준은 반드시 MD로 남김
- 민감도는 변동성만이 아니라 **방향(direction) + 크기(magnitude) + confidence**로 기록
