# HedgeMate 데이터/데이터분석 마스터 플랜 (MVP)

## Context
현재 상태:
- 70개 유니버스 수집/지표 계산/1차 리포트까지 완료
- 실행 스크립트 존재: `scripts/run_data_pipeline.py`
- 결과 증적 존재: `docs/04_실행결과/*`, `outputs/*`

이번 플랜 목적은 **데이터 신뢰도 + 분석 신뢰도 + 운영 반복성**을 MVP 수준으로 고정하는 것이다.

## Work Objectives
1. 데이터 품질판정(DQ)을 시장 구조에 맞게 고도화
2. 지표/HES를 재현 가능하고 설명 가능한 형태로 고정
3. 포트폴리오 입력 기반 분석을 연결해 실사용 가능한 결과 생성
4. 실행-리포트 자동화를 통해 일관된 운영 루프 구축

## Guardrails
### Must Have
- CSV 표준 유지 (`outputs/raw`, `outputs/processed`, `outputs/reports`)
- 위기구간 규칙 유지: SPY + (^KS200 우선, ^KS11 fallback), 20거래일 -8%
- 기존 실행 명령 유지: `python3 scripts/run_data_pipeline.py`

### Must NOT Have
- 실시간/분봉 확장
- 백테스트 고도화 범위 확장
- 유니버스(70개) 변경

---

## Task Flow (6 Steps)

### Step 1) Spec Freeze (문서-코드 기준선 고정)
**핵심 작업**
- 데이터명세/저장구조/실행방법/스크립트 간 규칙 불일치 제거
- 임시 기본값(Top-N=10, 단일자산 최대 20%, 공매도 금지) 공식 반영

**Acceptance Criteria**
- 핵심 규칙(출력포맷/벤치마크/위기구간/Top-N)이 문서와 코드에 1:1 대응
- 규칙 충돌 문구 0건

---

### Step 2) DQ 고도화 (캘린더 기반)
**핵심 작업**
- 미국/한국/암호화폐 거래일 기대치 기반 커버리지 계산
- 기존 단순 커버리지와 병행 비교 후 캘린더 기준을 기본 판정으로 사용

**Acceptance Criteria**
- DQ 결과에 `coverage_ratio_calendar` 포함
- PASS/WARN/FAIL 판정 근거가 리포트에 표시
- 동일 입력 재실행 시 DQ 결과 재현

---

### Step 3) 지표 엔진 신뢰화
**핵심 작업**
- 변동성/MDD/VaR/CVaR/Beta/상관 계산 검증 케이스 추가
- 계산 허용오차 및 결측 처리 규칙 문서화

**Acceptance Criteria**
- 샘플 자산 검증 결과(참조 계산 대비) 허용오차 이내
- 지표 누락/NaN 처리 규칙이 문서에 명시

---

### Step 4) HES 고도화
**핵심 작업**
- 유동성 패널티를 변동성 프록시 → ADV(평균거래대금/거래량) 기반으로 교체
- 컴포넌트 정규화/클리핑/결측 정책 고정

**Acceptance Criteria**
- HES 구성요소별 값이 결과 리포트에 노출
- 동일 data_version 재실행 시 Top-N 순위/점수 동일

---

### Step 5) 포트폴리오 입력 분석 연결
**핵심 작업**
- 비중(%) 입력 포트폴리오의 기존 vs 제안 비교(CVaR/MDD/변동성)
- 제약조건 위반 검증(합계 100%, 음수 금지, 단일자산 최대 20%)

**Acceptance Criteria**
- 샘플 포트폴리오 1건 이상 분석 성공
- 리포트에 기존 vs 제안 비교표 자동 포함
- 제약 위반 시 명확한 FAIL 메시지 출력

---

### Step 6) 운영 자동화 및 결과 품질 게이트
**핵심 작업**
- 실행 시 결과 3종(요약/초안/검토) 자동 생성
- 실행 완료 체크리스트(필수 파일/필수 컬럼/레코드 수) 자동 검증

**Acceptance Criteria**
- 1회 실행으로 `outputs/*` + `docs/04_실행결과/*` 자동 생성
- 필수 산출물 누락 시 실패 처리
- `docs/03_운영/03_진행현황.md`의 우선순위 최신화

---

## Verification Steps
1. `python3 scripts/run_data_pipeline.py` 실행
2. `outputs/reports/dq_result_YYYYMMDD.csv` 필수 컬럼 확인
3. `outputs/processed/features_summary_YYYYMMDD.csv` 지표 컬럼/결측 확인
4. `docs/04_실행결과/01~03_*.md` 생성 및 내용 정합 확인
5. 동일 조건 재실행으로 DQ/HES 재현성 확인

## Success Criteria
- DQ/지표/HES/포트폴리오 비교/리포트 자동화가 하나의 실행 루프로 동작
- 문서 규칙과 실제 산출물의 불일치 항목 0건
- 결과 리포트만으로 다음 의사결정이 가능한 상태
