# HedgeMate 데이터 고도화 작업 계획 (Phase 2)

## Context
현재 상태는 데이터 파이프라인 1차 검증 완료 단계다.
- 실행/검토 증적: `docs/04_실행결과/01_실행결과_20260305.md`, `docs/04_실행결과/03_결과검토_20260305.md`
- 실행 스크립트: `scripts/run_data_pipeline.py`
- 표준 문서: `docs/02_데이터표준/01_데이터명세_v1.md`, `docs/02_데이터표준/02_지표정의서_v1.md`

목표는 문서-실행 정합성을 맞추고, DQ/HES/포트폴리오 분석/리포트 자동화를 실무 사용 가능한 수준으로 고도화하는 것이다.

## Work Objectives
1. DQ와 위기구간 라벨의 재현성을 강화한다.
2. HES 계산을 실제 유동성 신호 중심으로 개선한다.
3. 포트폴리오 입력 기반 개선효과(CVaR/MDD)를 계산한다.
4. 실행-리포트 산출을 자동화해 운영 반복성을 확보한다.

## Guardrails
### Must Have
- 기존 실행 경로(`python3 scripts/run_data_pipeline.py`) 유지
- 산출물 3종(Raw/DQ/Feature) + 실행결과 md 자동 생성 유지
- 모든 신규 규칙은 문서(`docs/02_데이터표준/*`)와 동기화

### Must NOT Have
- 실시간/분봉 확장
- 백테스트 고도화 범위 확장
- 자산 유니버스(70개) 임의 변경

---

## Task Flow (5 Steps)

### Step 1) 표준 정합성 고정 (Spec Drift 해소)
**할 일**
- 위기구간 벤치마크/티커 표준을 단일 규칙(`SPY`, `^KS200` 우선 + `^KS11` fallback)으로 고정
- 저장 포맷 표준을 **CSV로 고정**하고 문서-코드 일치화

**대상 파일**
- `docs/02_데이터표준/01_데이터명세_v1.md`
- `docs/02_데이터표준/03_데이터저장구조_v1.md`
- `docs/03_운영/04_실행방법.md`
- `scripts/run_data_pipeline.py`

**Acceptance Criteria**
- 위기구간 정의가 문서/코드/결과문서에서 100% 동일 문구로 표기됨
- 저장 포맷 관련 상충 문구(예: CSV vs Parquet 혼재) 0건

---

### Step 2) DQ 고도화 (거래소 캘린더/커버리지 규칙)
**할 일**
- 미국/한국/암호화폐 캘린더 기준 기대 거래일 수 대비 커버리지 계산
- 현재 중앙값 기반 커버리지와 병행 비교 후 캘린더 방식으로 기본 전환

**대상 파일**
- `scripts/run_data_pipeline.py`
- `docs/02_데이터표준/01_데이터명세_v1.md`
- `docs/04_실행결과/03_결과검토_20260305.md` (검토 항목 갱신)

**Acceptance Criteria**
- DQ 결과 CSV에 `coverage_ratio_calendar` 컬럼 추가
- PASS/WARN/FAIL 판정이 캘린더 기준으로 산출됨
- 동일 입력 재실행 시 DQ 판정 결과 재현됨

---

### Step 3) HES 고도화 (유동성 패널티 정교화)
**할 일**
- 유동성 패널티를 변동성 프록시에서 거래량 기반 프록시(ADV 등)로 교체
- HES 각 컴포넌트 정규화/결측 처리 규칙 명문화

**대상 파일**
- `scripts/run_data_pipeline.py`
- `docs/02_데이터표준/02_지표정의서_v1.md`
- `docs/04_실행결과/01_실행결과_*.md`

**Acceptance Criteria**
- HES 구성요소별 계산식/정규화 규칙이 문서에 명시됨
- 실행결과 md에 HES 산출 근거(구성요소)가 포함됨
- 동일 `data_version` 재실행 시 Top10 순위/점수 동일

---

### Step 4) 포트폴리오 입력 분석 모듈 연결
**할 일**
- 비중(%) 입력을 받아 기존 vs 제안 포트폴리오 CVaR/MDD 비교 계산
- 제약조건 체크(비중합 100%, 단일자산 최대비중, 자산군 캡) 반영

**대상 파일**
- `scripts/run_data_pipeline.py` (또는 분리 모듈)
- `docs/03_운영/02_데이터분석리포트_템플릿.md`
- `docs/02_데이터표준/01_데이터명세_v1.md`

**Acceptance Criteria**
- 샘플 포트폴리오 입력 1건 이상에 대해 비교 결과 산출
- 리포트에 `기존 vs 제안`의 CVaR/MDD/변동성 표 자동 포함
- 제약조건 위반 시 명시적 FAIL 메시지 출력

---

### Step 5) 리포트 자동채움 + 운영 반복성 확보
**할 일**
- 실행 시 결과 요약/초안/검토 문서 자동 갱신
- `진행현황`의 다음 우선순위 자동 업데이트 규칙 정리

**대상 파일**
- `docs/03_운영/03_진행현황.md`
- `docs/03_운영/04_실행방법.md`
- `docs/04_실행결과/*`
- `scripts/run_data_pipeline.py`

**Acceptance Criteria**
- 1회 실행으로 결과 문서 3종(요약/초안/검토) 자동 생성
- 수동 편집 없이도 실행일자 기준 새 결과 파일 생성
- 실행방법 문서와 실제 산출 경로 불일치 0건

---

## Risks & Mitigations
- 리스크: 시장별 캘린더 차이로 결측 판정 과민/과소
  - 대응: 캘린더 기준 + 예외 규칙(상장일/거래정지) 분리
- 리스크: 유동성 데이터 한계(스프레드 부재)
  - 대응: MVP는 ADV 기반, 추후 스프레드 소스 도입 분리
- 리스크: 포트폴리오 제약 미확정으로 결과 해석 혼선
  - 대응: 기본 제약값(예: 단일자산 최대 20%)을 임시 고정 후 명시

## Verification Steps
1. `python3 scripts/run_data_pipeline.py` 실행
2. `outputs/reports/dq_result_YYYYMMDD.csv` 필수 컬럼 검증
3. `outputs/processed/features_summary_YYYYMMDD.csv` 지표 누락 검증
4. `docs/04_실행결과/01~03_*.md` 자동 생성/내용 정합 검증
5. 동일 조건 재실행 시 HES Top10 동일성 확인

## Success Criteria
- DQ/HES/포트폴리오 비교/리포트 자동화 4개 축이 모두 동작
- 문서와 실행 결과의 규칙 불일치 항목 0건
- 1회 실행 결과만으로 의사결정 가능한 리포트 세트가 생성됨
