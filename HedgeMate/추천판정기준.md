# HedgeMate 추천 판정 기준

## 1. 문서 목적
이 문서는 HedgeMate 엔진에서 결과를 **추천안**, **참고안**, **실패/제외**로 나누는 기준을 정리한 운영 문서이다.  
또한 사용자 검색 입력이 여러 자산과 연관될 때의 처리 원칙도 함께 정의한다.

이 문서의 목적은 다음과 같다.

- 결과 해석 기준을 단순하게 맞춘다.
- 추천안과 참고안을 혼동하지 않게 한다.
- 계산 가능 여부와 추천 가능 여부를 분리해서 본다.
- 검색 입력은 자동 오인식보다 **사용자 확인 기반 선택**을 우선한다.

---

## 2. 결과 분류 체계

HedgeMate의 결과는 크게 아래 3가지로 구분한다.

1. **추천안**
2. **참고안**
3. **실패/제외**

---

## 3. 추천안 기준

추천안은 아래 두 조건을 모두 만족한 경우에만 인정한다.

### 3.1 계산이 가능해야 한다
즉, 최소한 아래 단계가 정상적으로 완료되어야 한다.

- 예산/비중 구조가 유효하다.
- 조합이 실제로 구성 가능하다.
- 공통 수익률 구간이 존재한다.
- 포트폴리오 지표 계산이 가능하다.

### 3.2 Gate 조건을 모두 통과해야 한다
현재 Gate 기준은 아래와 같다.

1. **CVaR 개선 > 0**
2. **MDD 개선 >= 0**
3. **Stress 평균수익률 개선 >= 0**
4. **상관 또는 Beta 감소**
5. **유동성 기준 통과**
6. **DQ FAIL 자산 제외**

즉,

> 계산이 가능하더라도 위 조건 중 하나라도 통과하지 못하면 추천안이 아니다.

---

## 4. 참고안 기준

참고안은 아래 조건을 만족하는 경우이다.

### 4.1 계산은 가능하다
- 조합 생성 가능
- 수익률 계산 가능
- 최소한 비교 점수 또는 최종 점수 산출 가능

### 4.2 하지만 Gate는 통과하지 못했다
예를 들어:

- CVaR 개선이 없음
- MDD 개선이 없음
- Stress 개선이 없음
- 상관/Beta 감소가 없음
- 유동성 기준 미달
- DQ FAIL 자산 포함

이 경우 결과는 **정식 추천안이 아니라 참고안**으로 분류한다.

### 4.3 참고안의 의미
참고안은

> “계산상 비교는 되었지만, 현재 추천 기준을 충족하지 못한 대안”

으로 해석한다.

따라서 참고안은 **추천안의 대체물**이 아니라,  
추천안이 없을 때 보여주는 **참고용 결과**이다.

### 4.4 기본 노출 원칙
- **추천안이 존재하면 추천안을 우선 보여준다.**
- **추천안이 0건일 때만 참고안을 사용자에게 전면 노출한다.**
- 이 경우 경고 문구를 함께 표시한다.

기본 경고 문구:

> `Gate 통과 후보가 없어 참고안을 표시합니다. 리스크 관리가 어렵습니다.`

---

## 5. 실패 / 제외 기준

실패/제외는 “Gate 실패”보다 더 앞단의 문제다.  
즉, 비교 가능한 결과물 자체를 만들기 어려운 경우이다.

### 5.1 예산/조합 생성 실패
- KRW 예산이 너무 작아 1주도 매수할 수 없음
- 비중 cap 규칙 위반
- 음수 비중 발생
- 총 비중 100% 위반

### 5.2 수익률 계산 실패
- 공통 거래일이 너무 적음
- 포트폴리오 구성 수익률을 만들 수 없음
- 기준안 또는 제안안의 return series 생성 실패

### 5.3 지표 계산 실패
- 최소 관측치 부족
- 변동성/MDD/CVaR 등 핵심 지표 계산 불가

### 5.4 완전 제외 대상
- DQ FAIL이면서 분석상 핵심 입력으로 사용 불가능한 경우
- 유니버스 외 자산
- 해석 불가능한 입력

---

## 6. 데이터 부족 처리 원칙

데이터 부족은 곧바로 “완전 제외”를 의미하지 않는다.

### 6.1 허용 원칙
- 데이터가 부족해도 **가능한 범위 내 계산은 허용**한다.
- 후보 선별 단계에서 무조건 제거하지 않는다.

### 6.2 단, 추천안 승격은 별개다
- Gate에 필요한 핵심 지표가 계산되지 않으면
  **추천안(PASS)** 으로 승격하지 않는다.
- 이 경우는 참고안 또는 실패로 남을 수 있다.

즉,

> 데이터 부족 = 계산 허용  
> 데이터 부족 = 자동 추천 허용  
> 는 아니다.

---

## 7. 검색 입력 처리 원칙

### 7.1 검색창의 역할
검색창은 사용자가 자산을 쉽게 찾기 위한 **탐색 도구**이다.

즉,
- 회사명
- 자산명
- 티커

로 검색할 수 있다.

### 7.2 복수 매핑의 의미
복수 매핑이란, 하나의 짧은 검색어가 여러 자산 후보에 동시에 걸리는 경우를 말한다.

예시:

- `삼성`
  - 삼성전자
  - 삼성바이오로직스
  - 삼성생명
  - 삼성화재
  - 삼성SDI

즉,
`삼성`이라는 검색어를 넣었다고 해서  
엔진이 자동으로 “가장 비슷한 하나”를 고르는 것이 아니다.

### 7.3 검색 처리 원칙
- `삼성`처럼 넓은 검색어를 입력하면 관련 후보를 보여준다.
- 사용자는 그중에서 **정확한 자산**을 직접 선택한다.
- 예: `삼성` 검색 → `삼성전자` 또는 `삼성바이오로직스`를 클릭

### 7.4 자동 선택 금지 원칙
다중 후보가 가능한 경우:

- 엔진은 **가장 유사한 하나를 임의 선택하지 않는다.**
- 사용자 선택 없이 분석을 자동 실행하지 않는다.

즉,

> 검색은 후보를 좁히는 단계이고,  
> 최종 자산 확정은 사용자 선택 단계이다.

---

## 8. 본 문서에서 다루지 않는 것

아래 항목은 이 문서 범위에서 제외한다.

- Top N 노출 개수 정책
- UI 카드 배치 방식
- Gate 기준 자체 개편
- 고급 검색 랭킹 알고리즘

이 문서는 오직

1. **추천안 / 참고안 / 실패의 구분**
2. **검색어가 여러 자산과 연결될 때 자동 선택하지 않는 원칙**

만 다룬다.

---

## 9. 한 줄 요약

> **추천안은 계산 가능 + Gate 통과 결과이고, 참고안은 계산은 가능하지만 Gate를 통과하지 못한 결과이며, 실패는 계산 자체가 성립하지 않는 경우이다.**  
> **검색창은 자동 최다유사 선택기가 아니라, 사용자가 정확한 자산을 선택하도록 돕는 탐색 도구이다.**
